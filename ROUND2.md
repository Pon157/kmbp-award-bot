# 2 тур — опрос на сайте

Сайт (`app/`) полностью переписан под второй тур. **Первый тур продолжает работать** — старый сайт лежит в `app/r1/` и открывается по адресу `/r1/`.

**Кто куда попадает**
- Есть в списке допущенных (и владельцы) → новый сайт второго тура. В меню есть пункт «Первый тур» (ссылка на `/r1/`).
- Нет в списке, открыл в Telegram → автоматически перенаправляется на `/r1/` (первый тур работает как раньше).
- Нет в списке, открыл в браузере → экран «Второй тур скоро» + кнопка «Открыть первый тур в Telegram» (первый тур и раньше работал только внутри Telegram).
- Когда второй тур откроется для всех: Админ-панель → Обзор → выключить «Доступ только по списку ID». Папку `app/r1/` можно удалить, когда первый тур закончится.

У `/r1/` отдельная политика безопасности (разрешены inline-стили, которых требует старая вёрстка); у нового сайта — строгая.

> **Нужен свой сервер** (`SELFHOST.md`): вход из браузера использует cookie-сессии и `node:crypto`. Деплой через `tgcloud push` для этой версии не подходит.

## Обновление
1. Сделайте резервную копию (админка бота → выгрузка).
2. Замените файлы, `npm install`, перезапустите. Новые таблицы создаются сами.
3. В `.env`: `TRUST_PROXY=1` (если перед ботом Caddy/nginx — иначе защита по IP не будет работать), при желании `KMBP_SECRET=<длинная случайная строка>`. Адрес сайта в `APP_URL` должен быть `https://…` — тогда cookie получает флаг `Secure`.
4. Откройте мини-апп владельцем → меню (бургер) → **Админ-панель**.

## Что где
| Что | Где |
|---|---|
| Кто допущен (Telegram ID / @username) | Админ-панель → **Доступ**. Переключатель «Доступ только по списку ID» — на вкладке **Обзор** |
| Карточки проектов: баннер, название, описание, «выбор редакции», порядок | **Проекты** (баннер любой — сайт сам обрежет до 16:9 и сожмёт) |
| Результаты (видны только владельцам), подозрительные группы | **Результаты** |
| Удаление рисунков | **Рисунки** (или кнопка «Удалить» в галерее на карточке) |
| Модерация форума, темы, мьюты | **Форум** (или кнопки прямо в сообщениях) |
| Номинации (названия, порядок, включение) | как раньше — в боте. Карточки можно добавлять в любую, в том числе спонсорскую |

## Вход
- **В Telegram** — автоматически (подпись initData).
- **В браузере** — «Войти через Telegram»: сайт показывает число, бот присылает три числа, нужно нажать то, что на сайте. Домен в BotFather настраивать не нужно. Число защищает от «фишинговой» ссылки: чужой браузер вы не увидите, поэтому подтвердить вход за другого нельзя.

## Правила голосования (настраиваются в `tgcloud/lib/config.js` → `R2`)
- 1 основной голос в номинации (вес 1,0). Менять можно до 3 раз, не чаще раза в 10 минут.
- Дополнительный голос — 35 монет = 0,5 голоса; один на номинацию; нужен основной голос; изменить/вернуть нельзя (владелец может сбросить голоса человека — монеты вернутся).
- Рисунок: один на номинацию (на любой карточке). Переключатель «только один рисунок на весь тур» — в **Обзоре**.
- Карточки у каждого человека показываются в своём (стабильном) порядке — позиция в списке не влияет на итог (можно выключить).

## Защита от накрутки (слои)
1. Только вошедшие через Telegram; допуск — по списку ID (пока включён).
2. Один голос на человека и номинацию — уникальный индекс в базе, запись в транзакции.
3. «Билет» на голосование: привязан к человеку и номинации, одноразовый, действует не раньше чем через 3 с после открытия карточек.
4. Капча «я не бот» — один раз на 12 часов.
5. Лимиты частоты: на человека, на IP, на вход, на форум. IP и браузер хранятся только в виде хэшей с секретом сервера.
6. Лимит смен голоса и пауза между сменами; журнал всех попыток (`r2_vote_log`).
7. Антинакрутка в админке: общий IP, одна подсеть, одинаковые устройства, всплески голосов, «вся группа за один проект» → кнопки «исключить из подсчёта» / «удалить голоса».
8. Голоса забаненных и исключённых в итог не входят. Результаты пользователям никогда не отдаются.

## Безопасность
- Все API-запросы: подпись Telegram или HttpOnly+SameSite cookie (+ проверка Origin / Sec-Fetch-Site). Админ-действия проверяют владельца **на сервере** при каждом вызове.
- Строгий CSP без `unsafe-inline`/`unsafe-eval`: сайт собран без inline-скриптов и стилей; весь пользовательский текст попадает в страницу как текст (XSS исключён).
- Рисунки — только штрихи (числа), загрузить своё изображение нельзя. Баннеры проверяются (сигнатура JPEG, размеры, вес) и отдаются по подписанным ссылкам.
- Лимиты размера тела, таймауты запросов, лимиты по IP до проверки подписи.
- Что исправлено в старом коде — раздел «Аудит» ниже.

## Аудит существующего кода: что исправлено
- Не было CSP, `Referrer-Policy`, `Permissions-Policy`, HSTS → добавлены.
- Лимит запросов считался только после проверки подписи (дорогая операция доступна анониму) → лимит по IP стоит первым; добавлены таймауты `slowloris`.
- Капча: `Math.random` → криптографический генератор; создание капч без ограничений (можно забить базу) → лимит 10 за 10 минут на человека.
- Диагностика отказов в логе могла флудить → не чаще 3 записей в минуту с адреса.
- Тело запроса: 256 КБ для всех → 128 КБ (и 1,1 МБ только для загрузки баннера).

## Известные ограничения
- Спонсоры определяются по `username` — если спонсор сменит/освободит ник, его может занять другой человек. Лучше привязывать к Telegram ID (в этом обновлении не менялось).
- Учёт лимитов частоты — в памяти процесса: при перезапуске счётчики обнуляются; при нескольких экземплярах бота лимиты не общие (сейчас экземпляр один).
- Схема входа в браузере требует, чтобы человек писал боту: если человек заблокировал бота, войти в браузере он не сможет (в Telegram — сможет).
