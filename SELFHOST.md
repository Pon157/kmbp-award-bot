# Бот на своём сервере

Тот же бот и мини-апп, но без платформы Serverless: свой Node.js-процесс, своя база (SQLite), свой HTTPS-адрес.
Код бота (`tgcloud/`) не менялся — платформенные `sdk` заменены рантаймом в `server/`.

## Что нужно
- Сервер с **Node.js ≥ 22.13** (или Docker).
- **Домен с HTTPS** — Telegram открывает мини-апп только по https. Проще всего через Caddy (в `docker-compose.yml` уже есть).
- Токен бота и Telegram-id владельцев.

## Переезд за 6 шагов
1. **Выгрузка у вас уже есть** (`kmbp-backup-….json` — полная база, `kmbp-applications-….csv` — только заявки). Положите их на сервер.
2. **Файлы проекта** — на сервер, затем `npm install`.
3. **Настройки:** `cp .env.example .env` и заполните `BOT_TOKEN`, `OWNER_IDS`, `APP_URL`; при необходимости `TG_PROXY`.
4. **Загрузите базу** (бот ещё не запущен):
   ```bash
   npm run restore -- /путь/kmbp-backup-….json              # заменить всё
   npm run restore -- /путь/kmbp-backup-….json --merge      # только добавить недостающее
   npm run restore -- /путь/kmbp-applications-….csv         # только заявки из CSV
   npm run restore -- файл.json --dry-run                   # посмотреть, что внутри, ничего не меняя
   ```
5. **Запуск:** `npm start` (или `docker compose up -d --build`, или systemd — `kmbp-bot.service`).
   При старте бот сам создаёт недостающие таблицы, снимает старый webhook платформы и начинает принимать сообщения.
6. **Остановите бота на платформе** (два экземпляра одного бота мешают друг другу: в логе будет «конфликт»).

После переезда в админке есть кнопка **«Загрузить базу из файла»** — то же самое через бота (файл до 20 МБ; больше — командой выше).

> Картинки баннеров спонсоров в выгрузку не входят — загрузите их заново (раздел «Спонсоры»), иначе карточка донейшна не покажется.
> Если переезжаете на **другой** бот (новый токен), номера сообщений в старых карточках заявок станут недействительны — новые заявки будут работать как обычно.

## Прокси для Telegram API
Если с сервера нет доступа к `api.telegram.org`, задайте в `.env` одно из:
```
TG_PROXY=socks5://user:pass@1.2.3.4:1080     # SOCKS5 / SOCKS5h / SOCKS4
TG_PROXY=http://user:pass@1.2.3.4:3128       # HTTP(S)-прокси
TG_API_BASE=https://tg-mirror.example.com    # или своё зеркало API
```
Через прокси идёт **всё** общение бота с Telegram: приём сообщений, ответы, отправка и скачивание файлов (выгрузки, загрузка базы из файла).
Мини-апп открывается напрямую с телефона пользователя — прокси ему не нужен. MTProto-прокси (`tg://proxy…`) для ботов не подходят: это для приложений Telegram, не для Bot API.
В логах токен и пароль прокси скрыты. При запуске бот пишет «Telegram API — через прокси …» и «Бот: @имя» — если второй строки нет, смотрите предупреждение рядом.

## Приём сообщений
- `UPDATES=polling` (по умолчанию) — бот сам опрашивает Telegram. Работает за NAT/файрволом и через прокси.
- `UPDATES=webhook` — Telegram сам присылает обновления на `https://<домен>/webhook/<секрет>` (нужен публичный HTTPS). Секрет считается из токена.

## Рефералы
- Ссылка у каждого: `https://t.me/<бот>?start=ref_<id>` (кнопка «Пригласить друзей» на главном экране бота, команда `/invite`).
- Привязывается только **новый** пользователь (бот видит его впервые); себя пригласить нельзя; первый пригласивший остаётся.
- Реферал засчитывается, когда приглашённый подал **хотя бы одну заявку**. Считается на лету: удалили фейковые заявки — счёт сразу упал; забаненные не учитываются.
- Топ — в админ-панели: «Рефералы · топ» (постранично).

## Эксплуатация
- **Бэкап:** база — один файл `data/bot.sqlite` (+ `-wal`/`-shm`). Копируйте при остановленном боте или командой `sqlite3 data/bot.sqlite ".backup копия.sqlite"`. Бот сам раз в сутки шлёт владельцам JSON/CSV-выгрузки.
- **Обновление кода:** остановить → заменить файлы → `npm install` → запустить. Новые таблицы и колонки создаются сами.
- **Остановка:** `SIGTERM` — бот дорабатывает текущие запросы и закрывает базу.
- **Напоминания о голосовании** по умолчанию выключены — включаются в админ-панели («Монеты и напоминания»). Раз в минуту их проверяет внутренний таймер, ежедневный бэкап и чистка капчи — тоже по таймерам.
- **Безопасность:** API мини-аппа принимает только запросы с подписью Telegram (initData, проверка по токену), лимит запросов на пользователя, служебные модули наружу не отдаются. Файл `.env` не публикуйте.

## Проверка
```bash
node --no-warnings --import ./test/register.mjs test/run.mjs   # логика бота
node --no-warnings test/server.mjs                             # рантайм: прокси, подпись, API, webhook, загрузка базы
node --no-warnings test/tx.mjs                                 # транзакции
npm install jsdom --no-save && node test/ui.mjs                # интерфейс мини-аппа
```
